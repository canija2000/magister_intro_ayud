2 ¿Qué es HTML?

📘 Definición

HTML (HyperText Markup Language) es el lenguaje de marcado que estructura el contenido de una página web. Está formado por etiquetas (<h1>, <p>, <div>, …) que se anidan unas dentro de otras y forman un árbol, llamado DOM.

No necesitamos conocer todas sus características, pero sí entender cómo se comporta. Veamos el ejemplo paso a paso:

  1. Escribimos texto con etiquetas. Cada etiqueta abre (<p>) y cierra (</p>).
  2. El navegador lee ese texto y construye un árbol: lo que está dentro de una etiqueta es su hijo.
  3. Cada etiqueta puede tener atributos, de forma parecida a los atributos de un objeto en Python:
    • id: identificador único del elemento.
    • class: categoría que pueden compartir muchos elementos, por ejemplo class="price_color".
    • href / src: links o rutas de archivos.
    • style: estilos CSS (fuera del alcance del curso).
  4. Al hacer scraping recorremos ese árbol con código en vez de leer la página con los ojos.

3 Protocolos: HTTP y HTTPS

📘 Definición

HTTP (HyperText Transfer Protocol) es el conjunto de reglas con que un cliente (tu navegador o tu script de Python) le pide algo a un servidor (otro computador) y recibe una respuesta. HTTPS es lo mismo, pero con el mensaje cifrado.

Cada interacción ocurre así:

  1. El cliente envía una solicitud (request) con un método y una URL. El método indica la intención: GET pedir datos · POST enviar datos · PUT actualizar · DELETE eliminar.
  2. El servidor la recibe, la procesa y decide qué responder.
  3. Responde con un código de estado (¿salió bien?), headers (metadatos, como el tipo de contenido) y un cuerpo (el HTML o el JSON).
  4. El cliente procesa la respuesta: el navegador la dibuja y nuestro script la guarda en response.

    6.2Promedio por estación: ¿diario o anual?
    
        
    Con df['total'].mean() calculamos el promedio de la columna total. Pero cada fila
          es un día, así que eso es el promedio diario:
    
        
    $$\bar{x}_{\text{diario}} = \frac{1}{n}\sum_{d=1}^{n} \text{total}_d$$
    
        
    $$\bar{x}_{\text{anual}} = \frac{1}{|A|}\sum_{a\in A}\;\sum_{d \in a} \text{total}_d \;\approx\; 365\cdot
          \bar{x}_{\text{diario}}$$
    
        
    donde \(n\) es el número de días con datos y \(A\) es el conjunto de años.
    
        
    Las dos métricas ordenan las estaciones de la misma forma, pero la escala y la interpretación cambian. Es
          importante que el título del gráfico diga cuál se calculó.

    6.3Consideraciones sobre NaN
    
        
    Para encontrar el día más lluvioso de cada año, podriamos escribir
          df[df['año']==i]['total'].max() para cada estación. Si una estación no tiene datos ese
            año, el resultado es NaN. Luego se aplica max() de Python sobre esos valores,
          y ahí aparece la trampa:
        
    
        
      
          
    1. max() parte con el primer elemento como "mejor" y compara cada siguiente con
            x > mejor.
          
      2. 
          
    2. Cualquier comparación con NaN da False: 5 > nan es
            False y nan > 5 también.
          
      3. 
          
    3. Si NaN queda primero, nadie le "gana" y max() devuelve nan. Si
            aparece después, se ignora. El resultado depende del orden.
      4.

               .groupby(['region', 'año']).mean()                             # promedio entre estaciones
               .unstack('año'))                                               # una columna por año

chile_anual = chile.merge(anual, left_on='region', right_index=True)          # requiere mapear nombre ↔ número de región
chile_anual.plot(column=2024, cmap='Blues', legend=True)

    8 Conclusión
    
        
      
          
    • HTML es un árbol de etiquetas con atributos. Hacer scraping es recorrer ese árbol con
            find_all o select.
          
      • 
          
    • HTTP: cada requests.get es un request con su propio código de estado. Hay que
            revisarlo antes de procesar la respuesta.
      • 
          
    • Para obtener muchos datos hay que iterar sobre URLs (páginas, categorías, estaciones), cuidando el
            tiempo y los errores.
      • 
          
    • Una API entrega JSON [en general], que en Python es un dict. Hay que entender su jerarquía para
            aplanarla
            a un DataFrame.
          
      • 
          
    • Las credenciales van en un .env, nunca en el notebook.
      • 
          
    • Hay que saber qué se calcula: un promedio diario no es un promedio anual, y max() de
            Python no sabe manejar NaN.
